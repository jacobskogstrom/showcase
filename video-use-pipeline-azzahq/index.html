YouTube stand-out ideas + video-use pipeline integration

Source: Nate Herk — "Claude Video Editing Just Became Unrecognizable" (watched via /watch), cross-checked against the current home/AIOS/projects/media-agent-army setup. Notes from 2026-07-27.

What makes his output stand out (steal these)

  1. Liquid-glass card overlays, iOS-26 style. Translucent chrome-gradient cards over a dimmed talking-head background, not flat lower-thirds. Immediately reads "premium."
  2. Karaoke-style word-pop captions, not a static subtitle bar — words appear synced to speech, feels alive.
  3. Stat/chart callout cards ("+247%", bar chart) to punctuate a claim visually instead of just saying it.
  4. Literal visual metaphors for abstract claims — he said "show me an animation of editing out mistakes" with zero more detail, and got cards flashing red + a scissor wipe cutting them out. Prompting for the feeling, not exact specs, works when the style is already anchored (see #5).
  5. A written motion-philosophy / aesthetic-direction doc per video type — fixed 5-color palette, card grammar, timing rules. This is what lets one-line prompts ("do the usual intro") produce consistent, on-brand results instead of re-deciding style every time.
  6. Branded end-card pattern — last 5s: face-cam crops to vertical with rounded corners + drop shadow, shifts to one side, dark background reveals, "Thanks for watching / [tagline]" on the other side. Reusable sign-off template, not a random fade-to-black.
  7. Plan-mode before render. Claude proposes the full beat timeline (word-anchor, timing, card copy) and gets approved before spending tokens generating HTML/animations. Nate's 30s clip still cost ~238k tokens — planning first is what keeps that from ballooning further.
  8. Self-verifying renders. Told to screenshot its own output and check it against the ask — caught a face-occlusion bug and a stray grid-texture bug itself before Nate had to.
  9. Treats every finished video as training data — future prompts reference past compositions ("build a lesson like the last 5"), so the style compounds instead of resetting each time.

The actual pipeline gap vs. what we have

Our /make-a-video (Phase 2 of Media Agent Army) already does word-level transcription (transcribe_clip.py, Groq/OpenAI) + HyperFrames motion graphics — that part matches Nate's HyperFrames half exactly.

What's missing is his first step: automatic filler-word/retake/dead-air trimming straight off a raw take, before HyperFrames ever sees it. Today that trim is presumably still manual (Premiere or none). His tool for it is a real, separate open-source project:

  • github.com/browser-use/video-use — drop in raw footage, it finds and cuts filler words/false starts/retakes, hands back a trimmed clip + word-timed transcript. Built by the browser-use team, plugs into Claude Code (or Codex/OpenClaw) as a skill with shell access.

Proposed integration (do at desktop — multi-file, needs testing)

  1. Pull browser-use/video-use into the project (same pattern as HyperFrames: clone repo, let Claude Code read its skill/README, wire it in) as a Phase 1.5: raw clip in → trimmed clip + word-timed transcript out → feeds straight into existing /make-a-video.
  2. Add a motion-philosophy.md per recurring show (Bitesize episode format, Telling Technology short format) next to the existing HyperFrames creative docs — palette, card style, timing grammar — so future /make-a-video calls default to an established look instead of reinventing it.
  3. Check whether hyperframes-cli's check/snapshot/compare commands already give us the "screenshot and self-verify" loop Nate manually prompted for; if not, add it explicitly to the /make-a-video skill instructions.
  4. Bake "plan first, approve, then render" into the /make-a-video skill flow if it doesn't already gate on that — token cost control.
